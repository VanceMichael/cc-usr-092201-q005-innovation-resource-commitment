# 科创资源承诺兑现

把路演后"口头答应"的导师时段、设备场地、企业试验、融资接洽与政策协助，变成**带责任人、容量和期限、可确认、可追溯去向、按实际成果统计**的可履约服务。

## 业务流程

```
项目声明阶段与缺口
      │
资源目录匹配（具体时段 / 容量）
      │
提供方作出承诺（责任人 + 容量 + 答复期限 + 确认期限）   ← 作出即预占容量
      │
接受方确认                                           ← 确认后才实际占用
      │                                            └─ 逾期未确认：自动失效、容量回池
履约（取消 / 转交 / 延期 / 部分完成都必须登记去向 disposition）
      │
提供方登记履约回执 → 接受方核验
      │
转化结果（试制完成 / 验证完成 / 合作达成，须挂接平台承诺并核验）
      │
平台按已核验成果统计，不统计名片交换数与对接次数
```

关键规则（由 `src/domain.js` 强制执行，并由测试覆盖）：

- **项目先确认阶段与缺口**：缺口（`gaps`）带项目阶段、类型与期望满足时间；资源类型必须与缺口类型一致。
- **承诺四要素**：责任人、容量、答复期限、确认期限，缺一不可；期限不得早于承诺作出日。
- **不得双重承诺**：同一提供方同一时段，处于占用态的承诺总量不得超过时段容量。样例中 CMT-07 是对已占满时段的重复承诺尝试，被直接拒绝（`已拒绝`，无占用记录）。
- **确认才占用**：`等待接受方确认` 只预占容量；接受方在期限内确认后生成 `occupancies` 占用记录；逾期由 `expireUnconfirmed` 自动释放回池（CMT-04 即超时释放示例）。
- **去向必登记**：取消（容量释放去向）、转交（前后任责任人 + 原因 + 接受方知悉）、延期（新时段）、部分完成（已交付/应交付数量）都必须有 `disposition`/`handover` 说明。
- **下一对接联系人**：团队用 `nextActions(projectId, now)` 看待办，按截止时间排序，责任人转交后自动指向继任者（CMT-02：林栖凤 → 柯在）。
- **保密分级**：保密项目（PRJ-02 燧能科技）对无 `confidential_view` 权限的查看者只显示代号"保密项目（PRJ-02）"与必要需求；融资状态、接洽机构、估值等字段不进入提醒、回执与成果文本，`findConfidentialLeaks` 做静态扫描。
- **提供方视角**：`providerQueue` 看待接受方确认的承诺与待核验回执；`providerOutcomes` 确认自己的资源是否真正产生了成果。
- **兑现统计**：`fulfillmentStats` 只计 `verified=true` 且挂接了平台承诺的试制/验证/合作。OUT-03（私下签单、未挂接承诺）明确不计入，作为漏统示例。

## 资料范围

| 文件 | 内容 |
| --- | --- |
| `fixtures/domain.json` | v2 完整样例：3 个项目、9 个缺口、6 类资源（含时段容量）、10 条承诺、6 条占用、5 张回执、5 项转化结果 |

样例为虚构数据：人名、机构、电话与成果均为演示用，不含真实个人资料或凭据。

样例时间线（`scenario_as_of = 2027-01-20`）覆盖：

- 峰波微电子（PRJ-01）：导师辅导已核验、三个月场地消防检修导致 76/92 天部分完成并顺延、企业试验先取消（容量回池）后重新匹配且正等待确认、尽调时段超时释放、政策辅导已核验、一项私下合作不计入统计。
- 燧能科技（PRJ-02，保密）：脱敏导师评审已核验、隔断中试工位履约中、代号报名政策辅导；无权限人员收到的提醒不含融资状态。
- 同行者传感（PRJ-03）：其场地申请因 SLT-SITE-Q4 已被占用而被拒绝。
